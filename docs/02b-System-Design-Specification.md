## 2 总体概要设计

### 2.1 系统总体技术架构

系统采用 B/S 前后端分离多层架构，分为表现层、接入层、业务逻辑层、领域层、数据访问层、数据层和 AI 服务层：

- **表现层**：前端采用 Vue 3 + TypeScript + Vite 技术栈，配合 Element Plus 组件库，负责页面渲染与用户交互，通过 Axios 调用后端接口；
- **接入层**：Nginx 反向代理 + Spring Cloud Gateway 统一入口，负责静态资源分发、认证鉴权、请求路由与限流；
- **业务逻辑层**：后端采用 Spring Boot 3.5 + JDK 21，封装核心业务逻辑，提供 RESTful 风格 API 接口，按业务领域拆分为用户中心、课程中心、实训中心等独立模块；
- **领域层**：定义核心业务实体、值对象、仓储接口，与框架解耦；
- **数据访问层**：采用 MyBatis Plus 持久层框架，操作 MySQL 8.0 数据库，实现数据读写与事务控制；Redis 作为缓存层加速热点数据访问；
- **数据层**：MySQL 8.0 持久化存储，Redis 7 缓存，MinIO 对象存储；
- **AI 服务层**：Python FastAPI 独立服务，集成 LangChain / OpenAI SDK，通过多 Agent 协作完成文档分析、代码分析、需求对照、评分计算等 AI 分析任务。

```
┌─────────────────────────────────────────┐
│              表现层 (Vue 3 SPA)           │
├─────────────────────────────────────────┤
│        接入层 (Nginx + API Gateway)       │
├─────────────────────────────────────────┤
│    业务逻辑层 (Spring Boot 3.5 服务群)     │
├─────────────────────────────────────────┤
│          领域层 (Domain Entities)         │
├─────────────────────────────────────────┤
│  数据访问层 (MyBatis Plus + Redis Cache)  │
├──────────────────┬──────────────────────┤
│  数据层           │  AI 服务层            │
│  MySQL/Redis/MinIO│  Python FastAPI      │
└──────────────────┴──────────────────────┘
```

### 2.3 模块间交互关系

- 前端页面通过 HTTP 请求经 Nginx 反向代理到达 API 网关，网关根据路由规则转发至对应后端模块；
- 后端业务模块（成果中心、复核中心、报表中心）通过 HTTP 调用 AI 服务层（Python FastAPI），获取 AI 分析结果；
- 所有业务模块通过 MyBatis Plus 调用数据访问层完成数据库的增删改查操作，热点数据经 Redis 缓存加速；
- 认证鉴权、操作日志等横切功能通过 Spring 拦截器 / AOP 统一处理，所有接口自动生效；
- 文件上传经文件中心统一管理，实际文件存储于 MinIO 对象存储中。

### 2.4 系统部署设计

系统采用 Docker 容器化单节点部署方案：

- **前端**：Vue 3 项目构建为静态资源，由 Nginx 容器托管，同时作为反向代理转发后端 API 请求；
- **后端**：Spring Boot 项目打包为 Jar 包，容器化运行，提供 RESTful API 服务；
- **AI 服务**：Python FastAPI 独立容器运行，通过 Docker 内部网络与后端通信；
- **数据库**：MySQL 8.0 独立容器部署，数据持久化挂载宿主机目录；Redis 7 独立容器部署，用于缓存与 Token 管理；MinIO 独立容器部署，用于对象存储；
- **基础环境**：适配银河麒麟 V10 操作系统与 LoongArch 龙芯架构，全部容器通过 Docker Compose 一键编排启动；
- 所有服务通过 Docker 内部网络通信，宿主机仅暴露 Nginx 的 80 端口对外提供服务。

## 3 详细设计

### 3.1 核心业务流程设计

#### 3.1.1 用户登录流程

1. 用户在登录页输入账号密码，前端发送 POST /api/v1/auth/login 请求；
2. API 网关转发至认证服务，认证服务查询 MySQL 获取用户信息；
3. 服务端通过 BCrypt 验证密码哈希值；
4. 验证通过后生成 JWT Token 与 Refresh Token，将 Token 写入 Redis；
5. 前端存储 Token，根据用户角色动态加载路由，跳转至对应仪表盘；
6. Token 过期时前端自动调用 refresh 接口续期，续期失败则跳转登录页。

#### 3.1.2 实训任务发布流程

1. 教师在课程下创建实训任务，填写任务名称、描述、截止时间、提交方式；
2. 选择关联的评价标准（维度与权重）；
3. 选择目标班级，系统自动将任务下发给班级内所有学生；
4. 通知中心向学生推送任务发布通知；
5. 学生在「我的课程」中查看任务，在截止时间前完成提交。

#### 3.1.3 成果提交与 AI 分析流程

1. 学生选择提交方式（文件上传或 Git URL），提交实训成果；
2. 成果中心校验格式与截止时间，文件存储至 MinIO；
3. 提交记录写入 MySQL，异步触发 AI 分析；
4. AI Gateway 接收分析请求，Orchestrator 编排器并行调度多个 Agent：
   - DocAgent 分析文档质量（规范性、完整性）；
   - CodeAgent 分析代码质量（静态分析 + 语义分析）；
   - ReqAgent 对照需求完成度分析；
5. 各 Agent 结果汇总至 SummaryAgent，ScoreAgent 计算评分，ReportAgent 生成诊断报告；
6. 分析过程通过 SSE 实时推送进度至前端，学生可查看分析进度和结果。

#### 3.1.4 教师复核流程

1. 教师在审核工作台查看学生提交列表及 AI 诊断报告；
2. 逐条审核 AI 扣分项：采纳 / 驳回 / 调整扣分值；
3. 补充教师评语，确认最终评分；
4. 发布成绩，通知中心向学生推送成绩公布通知。

### 3.2 核心功能模块设计

#### 3.2.1 用户中心模块

**业务逻辑**：负责用户身份认证与信息管理。支持管理员/教师/学生三类角色，通过 RBAC 模型进行权限控制。密码采用 BCrypt 加密存储，登录后签发 JWT Token 实现无状态认证。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/auth/login | POST | 用户登录，返回 Token 与用户信息 | 公开 |
| /api/v1/auth/refresh | POST | Token 续期 | 需认证 |
| /api/v1/auth/me | GET | 获取当前用户信息 | 需认证 |
| /api/v1/user/profile | PUT | 修改个人信息 | 需认证 |

**异常处理**：
- 用户名或密码错误：返回 401，提示"用户名或密码错误"；
- Token 过期：返回 401，前端自动调用 refresh 接口续期；
- 账号被禁用：返回 403，提示"账号已被禁用，请联系管理员"。

#### 3.2.2 课程中心模块

**业务逻辑**：教师创建课程，填写课程名称、课程代码、学期、学分等信息。课程可通过课程-班级关联表下发给多个班级，通过课程-教师关联表指定授课教师。课程支持编辑和归档操作，归档后学生不可查看。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/courses | GET | 获取课程列表 | 教师/学生 |
| /api/v1/courses | POST | 创建课程 | 教师 |
| /api/v1/courses/{id} | PUT | 编辑课程 | 教师 |
| /api/v1/courses/{id} | DELETE | 归档课程 | 教师 |

**异常处理**：
- 课程代码重复：返回 400，提示"课程代码已存在"；
- 学生查看无权课程：返回 403，只展示已关联的课程。

#### 3.2.3 实训中心模块

**业务逻辑**：教师在课程下创建实训任务，配置任务描述、截止时间、提交方式（文件上传/Git URL/混合）、最大提交次数。任务通过班级关联表批量下发，学生端自动展示对应任务。教师可对未提交学生发起催办提醒。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/training-tasks | GET | 获取任务列表 | 教师/学生 |
| /api/v1/training-tasks | POST | 创建任务 | 教师 |
| /api/v1/training-tasks/{id} | PUT | 编辑任务 | 教师 |
| /api/v1/training-tasks/{id} | DELETE | 删除任务 | 教师 |

**异常处理**：
- 截止时间已过：学生端提交按钮置灰，提示"已过截止时间"；
- 催办操作：仅对未提交学生生效，已提交学生自动跳过。

#### 3.2.4 成果中心模块

**业务逻辑**：学生通过文件上传或 Git URL 两种方式提交实训成果。文件上传支持 ZIP/PDF/DOC/代码文件，单文件最大 50MB；Git URL 需系统验证仓库可访问性。提交后自动触发 AI 分析，学生可通过 SSE 实时查看分析进度。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/submissions | POST | 提交成果 | 学生 |
| /api/v1/submissions/{id} | GET | 查看提交详情 | 学生/教师 |

**异常处理**：
- 文件大小超限：返回 400，提示"文件大小不能超过 50MB"；
- Git URL 不可达：返回 400，提示"仓库地址无法访问，请确认地址正确"；
- 重复提交：根据任务配置的最大提交次数限制，超限提示"已达最大提交次数"。

#### 3.2.5 AI 分析中心模块

**业务逻辑**：接收成果中心的异步分析请求，通过 Orchestrator 编排器并行调度多个分析 Agent。DocAgent 分析文档规范性，CodeAgent 执行静态分析（Checkstyle/PMD/SpotBugs）与大模型语义分析，ReqAgent 对照需求完成度。所有分析结果汇总后生成诊断报告与评分建议，通过 SSE 实时推送至前端。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/ai/analyze | POST | 触发 AI 分析（异步） | 内部调用 |
| /api/ai/result/{submissionId} | GET | 获取分析结果 | 学生/教师 |

**核心算法设计 — 多维度加权评分算法**：

系统采用四维评价框架（完整性 / 规范性 / 正确性 / 创新性），教师可为每个任务配置各维度权重。评分计算流程如下：

1. 各 Agent 分别分析对应维度，每个维度生成扣分项列表（含扣分值、置信度、定位信息）；
2. ScoreAgent 汇总各维度扣分，按权重计算总分：`总分 = 100 - Σ(维度扣分 × 维度权重)`；
3. 低置信度（<0.7）的扣分项高亮标记，提示教师重点复核；
4. 支持多模型交叉验证：关键分析项同时调用 DeepSeek 与 OpenAI，结果不一致时标记为"需人工判断"。

**异常处理**：
- AI 调用超时（30s）：自动返回降级结果，提示"AI 分析超时，部分结果可能不完整"；
- AI 服务不可用：降级策略，标记分析状态为 FAILED，通知教师人工处理；
- API Key 未配置：返回友好提示，不阻塞核心业务流程。

#### 3.2.6 教师复核模块

**业务逻辑**：教师查看学生提交与 AI 诊断报告，逐条审核扣分项，支持采纳、驳回、调整三种操作。补充教师评语后发布最终成绩，通知中心向学生推送成绩公布通知。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/reviews/list | GET | 获取待审核提交列表 | 教师 |
| /api/v1/reviews/{id} | GET | 查看审核详情（含 AI 诊断） | 教师 |
| /api/v1/reviews/{id} | PUT | 提交复核结果 | 教师 |

**异常处理**：
- 重复审核：已终审的提交不可再次审核，提示"该提交已完成终审"；
- 终审操作不可逆：提交前二次确认弹窗。

#### 3.2.7 报表中心模块

**业务逻辑**：基于学生成绩与任务完成数据，生成多维度分析报表。班级学情报表展示成绩分布与完成率统计；学院质量报表支持跨班级对比与学期趋势分析。支持导出 PDF 和 Excel 格式。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/reports/class/{classId} | GET | 班级报表 | 教师 |
| /api/v1/reports/college | GET | 学院质量报表 | 教师 |
| /api/v1/reports/student/{userId} | GET | 学生个人报表 | 教师/学生 |

#### 3.2.8 系统管理模块

**业务逻辑**：管理员进行用户账号批量管理（新建/编辑/角色分配/状态启停）、班级管理（创建/编辑/学生分配）、系统全局参数设置（学期管理、上传大小限制、AI 模型参数、通知开关、维护模式）。

**接口定义**：

| 接口 | 方法 | 说明 | 权限 |
|---|---|---|---|
| /api/v1/admin/users | GET/POST/PUT | 用户管理 | 管理员 |
| /api/v1/admin/classes | GET/POST/PUT | 班级管理 | 管理员 |
| /api/v1/admin/config | GET/PUT | 系统配置 | 管理员 |
| /api/v1/admin/logs | GET | 操作日志查询 | 管理员 |

**异常处理**：
- 删除用户为高危操作：已关联课程或提交记录的用户不可删除，提示"该用户存在关联数据，无法删除"。

## 4 数据库设计

### 4.1 数据库选型与配置

- **选型**：采用 MySQL 8.0 关系型数据库，支持 ACID 事务、行级锁、丰富索引类型（B+Tree / FullText），成熟稳定，适配高校教学管理系统规模；
- **核心配置**：字符集 utf8mb4，存储引擎 InnoDB，开启事务支持、慢查询日志；数据持久化挂载宿主机目录，通过 Docker Compose 管理。

### 4.2 核心数据表结构

|---|---|---|---|

| email | VARCHAR(128) | — | 邮箱 |
| phone | VARCHAR(20) | — | 手机号 |
| avatar_url | VARCHAR(512) | — | 头像 URL |
| status | TINYINT | 非空、默认 1 | 0 禁用 / 1 启用 |
| is_deleted | TINYINT | 非空、默认 0 | 逻辑删除 |
| create_time | DATETIME | 非空 | 创建时间 |

### 4.3 数据关系与约束

- **表关联关系**：用户与角色通过 user_role 关联表实现多对多关系；课程通过 course_teacher 关联教师，通过 course_student 关联学生（含班级信息）；实训任务通过 course_id 关联课程；提交记录通过 task_id 关联任务、user_id 关联学生。
- **数据一致性约束**：用户创建时通过事务同时写入 user 表与 user_role 表；课程归档（status=0）后关联的实训任务自动对学生隐藏；用户删除采用逻辑删除（is_deleted=1），关联数据保留；密码 BCrypt 加密存储，不可逆。
- **业务规则约束**：username（学号/工号）全局唯一，由唯一索引保证；同一用户对同一任务在截止时间内的提交次数不超过 max_submit_count；文件上传大小限制（默认 50MB）由系统配置表管理。

### 4.4 数据持久化与运维说明

- 业务数据存储于 MySQL，对象文件存储于 MinIO；
- 例行备份由部署环境（Docker 宿主机 / 运维脚本）负责，**不作为管理员端产品功能提供**；
- 应用侧重保证逻辑删除、事务一致性与操作日志可审计，便于问题追溯。

## 5 安全设计

### 5.1 权限控制设计

- **权限模型**：基于 RBAC 角色权限模型，用户 - 角色 - 权限三级关联。系统预置三种角色：admin（系统管理员）、teacher（授课教师）、student（实训学生）；
- **控制粒度**：后端接口级权限控制（通过 Spring Security 注解 + 全局拦截器校验 Token 与接口权限），前端菜单级动态渲染（根据角色过滤可见菜单项）；
- **校验方式**：所有请求经 API 网关统一鉴权，校验 JWT Token 有效性与接口权限，无权限返回 403 状态码；
- **数据权限**：管理员可查看全部数据，教师可查看授课班级数据及全院/全校数据（教研职能），学生仅可查看个人数据。

### 5.2 常见安全防护

- **SQL 注入防护**：MyBatis 使用 #{} 预编译 SQL，禁止字符串拼接 SQL；Mapper XML 中参数统一使用 #{} 占位符；
- **XSS 攻击防护**：前端对用户输入内容进行 HTML 转义过滤，后端统一校验输入参数格式；
- **CSRF 防护**：接口请求携带 JWT Token 校验，验证请求来源合法性；
- **敏感数据保护**：密码 BCrypt 加密存储，不可逆；手机号、邮箱等个人信息按需脱敏展示；生产环境启用 HTTPS 加密传输；
- **文件上传安全**：文件中心对上传文件进行类型校验（白名单机制），限制文件大小，防止恶意文件上传；
- **AI 密钥安全**：大模型 API Key 通过环境变量注入，不入库存储。
